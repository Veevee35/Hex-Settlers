# V1.0.52 — Neural trainer desktop repair and tactical AI improvements

## Root cause and repair

The pre-existing `scripts/train_neural_ai_all_maps.js` ran a headless spectator-hosted self-play room, but the updated public multiplayer lobby logic required another human before the host could spectate. Each game therefore blocked while waiting for spectator confirmation and then retried. Separately, the host room quota (4 active rooms/account) and room creation limiter (6/minute) could interrupt rapid training batches, and error responses were not surfaced until a timeout.

The repair permits host-as-spectator and bypasses the room creation quota **only** when *all* of `AI_TRAINING=1`, `NODE_ENV=test`, and `HOST=127.0.0.1` hold. These are set by the isolated child process launched by the trainer. Public deployments remain governed by the original quotas, login limits, and spectator/host restrictions. The isolated self-play server now deletes abandoned rooms when their last peer disconnects, avoiding buildup after a failed match.

The main trainer defaults to three concurrent games and increases timeouts for larger player counts. The distributed/evolutionary launchers now create their ignored `scripts/output` directory before writing checkpoints, and use conservative desktop defaults instead of launching excessive concurrent server processes. All trainer entry points use local-only model writes so inherited Cloudflare state configuration cannot upload test data or candidate weights. The trainer now reports server errors and closed sockets immediately, checks for crashed server startup, caps retries at three per game, atomically writes the model/report, and retains temporary batch checkpoints after failure. A cross-platform single-game, **non-destructive** smoke test has been added. Its temporary model cannot overwrite `neural_ai_model.json`.

## Tactical AI improvements

The expert neural chooser continues using the trained neural output, but retains additional tactical information in action ranking:

- high-pip, diverse, strategically valuable settlement sites; city upgrade locations
- high-value road/ship discovery actions on Fog Island, including elevated exploration urgency when the player has no available settlement space
- expansion routes that unlock new legal settlement positions
- progress toward Longest Road, pursuing Knights for Largest Army, and development cards when a VP card could close the game
- stronger penalty against non-enabling bank trades, with nontrivial minimum score improvement before accepting bank trades
- strict refusal to hand a leader within two points of winning scarce grain, ore or low-income resources
- refusal to complete an opponent's winning city/settlement/development purchase through a trade
- substantially higher relative benefit requirements for non-enabling player trades

These are heuristic improvements to action selection, **not claims of statistically measured higher win rates**. The supplied neural model weights are preserved; self-play after deployment retrains them from completed games. The training curriculum now includes New Shores 5–6, Classic 7–8, and authored 7–8 scenarios.

## Windows desktop / Codex commands

Open PowerShell in the `Hex-Settlers` project directory (where `package.json` lives):

```powershell
node --version                   # Node.js 20 or newer
npm ci                           # dependencies must be installed
npm run test:neural              # fast deterministic tactical tests
npm run train:neural:smoke       # one AI-only game; does NOT change your real model
```

For an actual 100-game training run:

```powershell
$env:SIMS='100'
$env:BATCH_SIZE='10'
$env:CONCURRENCY='3'
$env:MAP_SET='standard'           # excludes custom Test Builder maps
npm run train:neural
```

For a 500-game curriculum including custom maps, change `MAP_SET` to `all`. To train on independent shards, use `npm run train:neural:distributed`; for candidate selection, use `npm run train:neural:evolutionary` with `SIMS` divisible by `SELECTION_INTERVAL`. For a larger desktop rig, adjust `CONCURRENCY` gradually. Outputs are written under ignored `scripts/output/`. A successful training run updates the root `neural_ai_model.json`; commit this updated model intentionally to deploy it to game servers. Never run the trainer against the public hostname or a live user database.

If a run fails, the error now points to a specific scenario and game. Temporary self-play checkpoints are preserved and the original model is not overwritten by an incomplete run. The JSON checkpoint is diagnostic; rerunning does not automatically resume from it.

## Verification

Static syntax and tactical unit tests can run without network access. A complete end-to-end headless neural training smoke test and build require the `ws` package and the other npm dependencies installed. They should be run on the desktop/CI when package installation is available.
