# Hex Settlers V1.0.46 — Discord login, account linking, client analytics, installable mobile game

## Release content

This is a complete V1.0.46 source ZIP, based on the uploaded V1.0.45 build. `public/discord-activity.bundle.js` is **already compiled and included**, with a SHA-256 checksum. `npm run build:discord` regenerates and checks the browser bundle offline; no placeholder or SDK npm download is required for this step. The Discord adapter implements a subset of the upstream protocol, not the entire official SDK.

1. **Discord as a fourth OAuth sign-in method.** The normal website now shows Discord alongside Google, GitHub and Cloudflare on login and CAPTCHA-protected registration. It uses server-side authorization-code + PKCE, an encrypted state cookie, state/issuer validation and `https://discord.com/api/users/@me` to obtain the immutable Discord user ID. The Discord client ID/secret already used for Activities are reused for regular web OAuth. Identity is NEVER inferred from a matching email address or username.
2. **Multiple providers on one existing player.** In Account Management, sign in with your current Hex Settlers account and select **Link** for every extra provider. You may link Google, GitHub, Cloudflare and Discord to the same account, plus add a password and verified recovery email. You cannot connect an external identity already owned by another player; use the existing admin account-merging workflow in that case. Each provider currently supports one linked identity per account; all four providers can coexist. Email verification no longer clears `oauthAccounts` or destroys existing account history. When first establishing/changing a password, existing sessions are still invalidated for safety.
3. **Discord Activity automatic login.** The Activity asks the Discord SDK for a one-time authorization code, exchanges it on the server and verifies the Discord user is a participant in the specific Activity instance. If and only if that immutable Discord ID is already linked to a non-admin Hex Settlers account, the server issues a scoped cookie and an Activity join ticket. The player is automatically signed in and joins the correct lobby. An unlinked user sees the normal account login/registration, without insecure auto-merging. Admin accounts cannot bypass administrator MFA via this route.
4. **Admin → Client Analytics.** Shows current authenticated players and connections by Desktop browser / Discord Activity / Mobile browser or installed PWA; unique accounts over 1 / 7 / 30 / 90 days; a trend chart; and active player names with their client types. One account using two clients is counted once in each type but only once in the overall unique total. Per-user daily categories are stored within the existing persistent `users.json` R2 state; no extra R2 binding, API secret or database migration is needed. Collection begins when V1.0.46 is deployed. No IP addresses or unique device identifiers are recorded in this analytics record. Device detection may be inaccurate for browsers that suppress mobile signals.
5. **Mobile login → Download App · Add to Home Screen.** The mobile-only button uses a browser install prompt when available, or shows iOS/Android install instructions. `manifest.webmanifest`, 192px/512px icons, service worker and standalone app mode are included. This installs the existing website as a PWA / home-screen app; it is **not an Android APK or an iOS App Store download**. It does not appear inside Discord or on desktop logins.

## One REQUIRED Discord Developer Portal change

Your screenshot shows **no registered OAuth2 Redirects**, which explains `OAuth2 Error: invalid_request: Missing "redirect_uri" in request.` This is NOT the Interactions Endpoint field.

Open [Discord Developer Portal](https://discord.com/developers/applications) → **Hex Settlers** → **OAuth2** → **Redirects** and add both of these exact URLs:

```
https://127.0.0.1
https://hexsettlers.org/api/auth/oauth/discord/callback
```

- `https://127.0.0.1` is Discord's published placeholder redirect for an embedded Activity using the SDK's `authorize` RPC, which manages the return to the Activity.
- `https://hexsettlers.org/api/auth/oauth/discord/callback` is the confidential server-side OAuth redirect for **Discord as a web login provider**. Both origins are separate on purpose.
- Click **Save Changes**. Keep **Interactions Endpoint URL blank** unless you separately implement and verify signed Discord slash-command callbacks.
- The Discord OAuth2 Public Client toggle may stay **off**: the web server performs confidential code exchanges with `DISCORD_CLIENT_SECRET`.

In Cloudflare Worker secrets, keep these existing values set for the production Container:

```
DISCORD_CLIENT_ID=1477895334406656101
DISCORD_CLIENT_SECRET=(your private Discord OAuth client secret)
DISCORD_BOT_TOKEN=(your private Discord bot token)
OAUTH_STATE_SECRET=(your existing strong secret, 32+ characters)
```

If Cloudflare rebuilds a Container from different Worker variable names, check that these four are configured in the **actual production Worker** and not only staging. `cloudflare/container-worker.mjs` forwards these existing settings into the game container. Never put client secrets or bot tokens into JavaScript, GitHub commits or player browsers.

## Publishing V1.0.46

1. Extract the ZIP and copy **everything inside `Hex-Settlers`** into your existing GitHub checkout. Keep the `.git` folder and Cloudflare secrets, and do **not** replace or clear R2 saved game or player data.
2. Run the local, dependency-free verification:

   ```powershell
   node scripts/verify-discord-bundle.cjs
   node --check server.js
   node --check public/app.js
   ```

3. Use `git add -A` then confirm these files are staged and will be pushed:

   ```powershell
   git ls-files public/discord-activity.bundle.js public/discord-activity.bundle.sha256 public/manifest.webmanifest public/install-app.js
   ```

4. Commit / push to the existing repository. Preserve your existing Worker and Container configuration, custom domains, and GitHub → Cloudflare deployment. Current build command can stay:

   ```bash
   npm run build:discord && npm install --prefix cloudflare --no-audit --no-fund && node scripts/stamp-git-build.cjs
   ```

5. Confirm build logs say `Discord Activity client bundle verified`. Check `https://activity.hexsettlers.org/discord-activity.bundle.js` returns JS, not the old diagnostic placeholder. Check `https://hexsettlers.org/manifest.webmanifest` returns a JSON web manifest. Reopen the Discord Activity after installing the new version.

### Acceptance checklist

- Normal website → login page shows **Discord**, Google, GitHub, Cloudflare. Discord login returns to the regular Hex Settlers player; registering a *new* Discord identity requires CAPTCHA.
- Signed in with Google → Account Management → Link Discord → OAuth approve → same player ID/stats after returning. Link GitHub/Cloudflare the same way. Add verified email/password; all links persist.
- Sign out from Hex Settlers. Join a Discord voice-channel Activity with that **linked Discord account**. The Activity should sign in automatically and join its private lobby without a Hex Settlers password.
- Join with a different, unlinked Discord account. It must **not** auto-login to somebody else's Hex Settlers account. Normal sign-in / CAPTCHA browser pairing remains available.
- Join with two linked Discord players. Both should land in the same Activity lobby; a second Activity instance creates a different lobby.
- `admin.hexsettlers.org` → Admin Management → Client Analytics. Check real connected Browser, Discord and Mobile counts and daily totals. Data accumulates only after this release.
- Android mobile browser → login → Download App. Confirm install prompt or instructions, add icon. On iOS, select Share → Add to Home Screen; test standalone launch.
- Password CAPTCHA thresholds (2 failures, 5 attempts/20-minute lock) and admin password + TOTP remain intact.

### Test status and limitations

- 53 selected security, account, Discord routing, CAPTCHA, PWA and analytics tests passed before final packaging; relevant Node syntax checks and Discord-bundle integrity checks passed.
- Full legacy repository tests contain unrelated failures from UI assertions written for older game releases; server integration tests also require npm `ws`, which is not installed in this sandbox. Consequently, the full test suite did not pass here.
- Live Discord OAuth authorization, Discord mobile compatibility, Cloudflare Container startup, browser install prompts and real server multiplayer were **not** validated from this sandbox. They must be tested on your deployment.
