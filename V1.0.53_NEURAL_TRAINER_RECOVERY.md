# Hex Settlers V1.0.53 — resilient evolutionary neural training

## Cause of the reported failure

The V1.0.52 20,000-game evolutionary launcher aborted when its third candidate exceeded the game timeout on `classic78` and exhausted two retries. Multiple other `classic78` sessions had already timed out; the trainer was not able to tell a stalled game from a slow game because headless mode intentionally did not broadcast in-game progress. Cosmetic `sfx` WebSocket notifications obscured this in its last-message diagnostic. The available logs do **not** establish whether the AI was deadlocked or simply unable to finish that particular board within its CPU/time budget.

V1.0.52 **did** save per-batch checkpoints under each candidate's `report.json.checkpoint.json`; completed generations publish selected weights. Those earlier checkpoints were not resumable by the launcher, so a restart previously discarded unfinished-generation work.

## Changes

1. Training-only 1-second lightweight progress messages report engine actions, turn number, and phase without serializing full game state. The client kills a game after a configurable *lack of game progress* (75 seconds by default), a max-turn cutoff (900 by default), or the existing wall-time limit. Sound effects are suppressed in isolated local training only, eliminating thousands of unnecessary WebSocket messages. These changes do not affect public games.
2. Expensive neural action-budget lookahead is capped to 4 actions per turn **in local training only** (configurable via `TRAINING_AI_ACTION_BUDGET`, range 2–8). Live neural AI retains its full budget of 8. This improves throughput but may change the training-play distribution, so evaluate the eventual weights before deploying them.
3. A scenario that fails twice is replaced by a *real match on a different board*, first trying the same number of players. No timed-out game is counted as a training completion. Replacements are called out in the final report under `scenariosReplaced`. Repeatedly failing scenarios enter a temporary 80-slot cooldown and are then retried. You can change retry, quarantine, and replacement settings via the environment.
4. After several consecutive failures, an isolated batch server is considered unhealthy and restarted. By default, the trainer may restart a batch twice. Only completed batches are committed, so a process failure cannot overwrite the last known-good trained model with incomplete weights.
5. Candidate progress is saved atomically with a matching neural model after each completed batch. With `RESUME_TRAINING=1`, the trainer validates and reloads that checkpoint. The evolutionary launcher accepts `RESUME_RUN_DIR` to reuse completed candidates and selected generations, and supports the *unfinished first-generation V1.0.52 layout* if at least one candidate still has its untouched original model.
6. Failed attempts and scenario cooldowns are recorded to `report.json.failures.log` alongside the existing `.checkpoint.json` / `report.json`. Candidate files and generation selection snapshots remain under the per-run `.neural-evolution-*` directory.

## Resuming the failed V1.0.52 run on Windows PowerShell

Use the version 1.0.53 project (merge source changes instead of replacing any independent newer development), then run `npm ci`.

```powershell
cd 'C:\Users\Ben.Thomas\Documents\GitHub\Hex-Settlers'
npm ci
npm run test:neural

# Inspect old evolutionary runs; select the one that failed at ~750 games.
Get-ChildItem '.\scripts\output' -Directory -Force -Filter '.neural-evolution-*' |
  Sort-Object LastWriteTime -Descending |
  Select-Object FullName, LastWriteTime

$env:RESUME_RUN_DIR = 'C:\Users\Ben.Thomas\Documents\GitHub\Hex-Settlers\scripts\output\.neural-evolution-REPLACE_WITH_ACTUAL_FOLDER'
$env:SIMS = '20000'
$env:SELECTION_INTERVAL = '1000'
$env:SHARDS = '4'
$env:BATCH_SIZE = '25'
$env:CONCURRENCY = '2'
$env:MAP_SET = 'standard'
$env:KEEP_TRAINING_TEMP = '1'
$env:IDLE_TIMEOUT_MS = '75000'
$env:MAX_TRAINING_TURNS = '900'
$env:TRAINING_AI_ACTION_BUDGET = '4'
$env:MAX_ATTEMPTS_PER_MAP = '2'
$env:MAX_MAP_REPLACEMENTS = '6'
$env:MAX_BATCH_RESTARTS = '2'
$env:MAP_QUARANTINE_FAILURES = '3'
$env:MAP_QUARANTINE_GAMES = '80'

npm run train:neural:evolutionary
```

**Important:** preserve the `.neural-evolution-*` checkpoint folder before using the updated source. If the user previously deleted it, completed unselected work cannot be recovered, even though already selected generation weights may survive in the root model. Never pick a checkpoint from a different model or different simulation configuration. V1.0.52 only checkpoints completed batches; a few sessions from its unfinished batch may need to be replayed.

To start a **new** 20,000-game run, remove the `RESUME_RUN_DIR` environment variable, then execute the same command:

```powershell
Remove-Item Env:\RESUME_RUN_DIR -ErrorAction SilentlyContinue
npm run train:neural:evolutionary
```

If you choose different SHARDS, SIMS, SELECTION_INTERVAL or MAP_SET, start a new run rather than reusing old candidate progress. Keep `TRAINING_OUTPUT` unset or use exactly the old output configuration when resuming. You can tune `CONCURRENCY` conservatively; four shards by two concurrent games means up to eight simulated matches at once. For an overloaded system, use `CONCURRENCY=1` to reduce contention.

## Validation and limitations

- `node --test test/neural-strategy.test.js test/neural-trainer-recovery.test.js` passes, including a synthetic V1.0.52 recovery with a completed candidate and a checkpoint-only candidate.
- `node --check` passes on modified JavaScript, and `tsc -p tsconfig.bootstrap.json` passes.
- A real AI-versus-AI game and stress test have **not** been run in this sandbox because the npm `ws` dependency is not available, and the public npm registry cannot be resolved here. Run `npm run train:neural:smoke` on the desktop before resuming.
- Restarts, replacements, and cooldowns reduce the impact of failing scenarios, but do not promise that all 20,000 games will complete if the engine is consistently broken, repeatedly out of memory, or all scenario variants fail. They do not fabricate victories or silently count aborted games.
- `standard` excludes Test Builder. The original curriculum still contains 4-, 6-, and 8-seat games, not separate 5- and 7-seat curricula.
