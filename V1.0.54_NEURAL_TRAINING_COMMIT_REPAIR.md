# Hex Settlers V1.0.54 — neural training commit repair

## Why this release exists

On V1.0.53, a completed Classic AI game reported `[train] 1/1`, but the batch later failed with `Model trainedGames=50584; expected 50585 after batch 1`. A terminal game state is not proof that the training update succeeded and the weights were saved. The V1.0.53 runner checked the mismatch only after the batch was finished. The user's original weights were not overwritten by the failed smoke test.

## Changes

- The isolated headless training server exposes a **local-only** `get_training_receipt` request, gated on `AI_TRAINING=1`, `NODE_ENV=test`, and `HOST=127.0.0.1`.
- The receipt acknowledges the **game ID** and **neural model trainedGames count only after the model's atomic disk write has finished**. It reports a useful error if the game did not train or its model write failed.
- The self-play runner requires that receipt before recording a successful game. Failed writes, missing neural seats, and receipt mismatches are retried/quarantined through the existing resilience path; none are silently counted as training games.
- The trainer validates that every filled AI seat is `neural_net`, preventing successful-but-untrained AI matches.
- An idempotent, headless-only terminal-state safeguard attempts to train games that reached game-over without executing the usual victory training callback.
- Model write failures are propagated and converted into receipt errors instead of silently swallowed or left as unhandled promise rejections.
- Batch-level model-count mismatches are now retried as a full, uncommitted batch; the runner logs captured training-server output to diagnose persistent cases.
- Added 4 regression tests covering the actual model trainer, one-time updates, failed writes, and the receipt protocol. The existing checkpoint/resume formats are unchanged.

## Update safely (PowerShell)

1. Back up `neural_ai_model.json` and the entire `scripts/output` directory in your existing Git checkout before merging the new source. Do not delete or overwrite the old checkpoint directories.
2. Copy the V1.0.54 `Hex-Settlers` files into your existing repository. Keep any local environment/secrets and your existing training output directory.
3. Run:

```powershell
npm ci
npm run test:neural
npm run train:neural:smoke
```

The smoke command copies your current model into a disposable folder, runs a real Classic game, and checks that a matching trained model is saved. It does not change the original model. The real-game smoke **still needs to be run on your desktop**; this build environment lacks the downloadable `ws` dependency and cannot run the full local WebSocket simulation.

## Resume 20,000 simulations

If you still have the previous evolutionary run directory (typically under `scripts/output/.neural-evolution-*`), point `RESUME_RUN_DIR` at the **actual** directory printed by the previous run, not a placeholder. Keep the original SIMS, SELECTION_INTERVAL, SHARDS, MAP_SET, and base model for that run. For example:

```powershell
$env:RESUME_RUN_DIR='C:\full\path\to\.neural-evolution-existing-run'
$env:SIMS='20000'
$env:SELECTION_INTERVAL='1000'
$env:SHARDS='4'
$env:BATCH_SIZE='25'
$env:CONCURRENCY='2'
$env:MAP_SET='standard'
$env:KEEP_TRAINING_TEMP='1'
npm run train:neural:evolutionary
```

If starting a new run instead of resuming, execute `Remove-Item Env:RESUME_RUN_DIR -ErrorAction SilentlyContinue` first. For diagnostics, failed games append to each candidate's `report.json.failures.log`; training server error details are included when batches fail.
