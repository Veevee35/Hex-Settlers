# Hex Settlers V1.0.55 — local neural trainer GUI and CUDA refinement

This release adds a **local browser-based training control center** and an **optional PyTorch/CUDA batch optimizer** to the existing isolated evolutionary self-play workflow. It retains the original 17-input / 8-hidden / 1-output neural-model JSON format, `trainedGames` accounting, candidate selection, checkpoint recovery, and scenario scoring from V1.0.54.

## Install on Windows (one time)

1. **Back up `neural_ai_model.json` and all of `scripts/output/`** from your current project. These contain learned weights and resumable training. When merging the new ZIP into an existing Git checkout, **do not overwrite your newer trained model or delete your output folders**.
2. Install Node.js 20+ if necessary and extract/merge the complete ZIP into your project folder.
3. **Double-click `Start-Neural-Trainer.cmd`** in the project root. The launcher runs `npm ci` if the `ws` package is missing and starts the dashboard in your normal browser. The local URL is printed in the launcher window (it uses a random available port on `127.0.0.1`). Keep the launcher open while training.
4. For the GPU option, separately install an NVIDIA driver and a **CUDA-enabled** version of PyTorch for your selected Python environment. Use [the official PyTorch selector](https://pytorch.org/get-started/locally/) to obtain the current Windows / pip / CUDA installation command. You do not need a separate CUDA Toolkit for most prebuilt PyTorch wheels.
5. Enter that Python executable in the dashboard's *Python executable* field (e.g., `python` if it resolves to the intended environment, or the full path to your venv's `python.exe`), then click **Detect GPU**. This must say **CUDA READY** and identify your GPU before choosing **NVIDIA CUDA (required)**. Auto will explicitly fall back to CPU if the selected Python has no compatible CUDA-enabled PyTorch.

You can also open the GUI from a terminal with `npm run train:neural:gui`, but **daily training does not require PowerShell**.

## Suggested configuration for 20,000 simulations

| Dashboard control | Recommended initial value |
| --- | --- |
| Training session | New run, or choose a saved `.neural-evolution-*` folder to resume |
| Total simulations | 20000 |
| Games / generation | 1000 |
| Model candidates | 4 |
| Games / checkpoint batch | 100 (use 25–50 if you want less unsaved work) |
| Simultaneous games per candidate | 2 (up to 8 CPU simulations across 4 candidates) |
| Scenario set | **Standard** to exclude Test Builder |
| Learning backend | Auto, or NVIDIA CUDA after GPU detection succeeds |
| CUDA epochs per batch | 3 |
| CUDA minibatch size | 256 |

Press **Start training**. Progress and logs update without touching the production server. CPU workers simulate game turns and retain the original fast one-game updates. In CUDA mode, each finished-game training receipt also writes supervised features and targets into a temporary local dataset. After each simulation batch **and after the isolated game server shuts down**, a fresh Python/PyTorch CUDA optimizer runs batched backpropagation and updates the same JSON model. A conservative finite-loss check prevents a malformed CUDA batch from being promoted. CUDA training preserves `trainedGames`; only completed self-play games increment this counter.

A complete generation scores its candidates and propagates the selected model's weights to the next generation, as before. The selected model is written to the root `neural_ai_model.json` after every generation.

## Stop, resume, and recover

- **Pause after checkpoint** writes a local pause request. Each active candidate finishes its current batch, saves a checkpoint, and exits without marking unfinished games complete. The run folder remains under `scripts/output/.neural-evolution-*`.
- To **resume**, use the Training session selector to choose that exact run folder. The dashboard reloads its saved generation parameters when available. Other settings (batch size, GPU mode, concurrency) may be changed; keep total simulations, games/generation, shards, and scenario set matched to the original run.
- **Emergency stop** kills the entire descendant trainer process tree. It can lose the currently uncommitted batch, not prior committed batches. Resume through the same selector afterwards.
- Errors, GPU diagnostics and normal events are written to `scripts/output/neural_gui_<session-id>.log`. Per-candidate `.checkpoint.json` and failure logs remain in the generation folders.
- The local dashboard keeps the most recent session visible while open. It does **not** schedule jobs to continue when the computer is off or asleep.

## What CUDA does and does not accelerate

**CUDA accelerates the *batched neural gradient-refinement phase***, not game simulation, legal-action search, map generation, or CPU inference. The present model is tiny (17 inputs, 8 hidden units, one output), so on some configurations CPU simulation and Python/GPU initialization remain the bottlenecks. Enabling CUDA does **not guarantee** that a 20,000-game job finishes sooner; measure CPU and CUDA runs on the same settings. The dashboard visibly reports when CUDA is actually activated and whether individual GPU refinements updated weights.

The `standard` curriculum currently contains **19 authored map templates**, covering 4-, 6-, and 8-seat games, including New Shores 5–6 and New Shores 7–8, and excludes both Test Builder variants. **Exactly 5-player and 7-player lobbies are not yet separately simulated**, and some 7–8 Scattered Tiles/Cartographer variants remain outside the existing curriculum; the GUI does not disguise this gap.

## Security

The dashboard binds only to `127.0.0.1` on a random available port, requires same-origin + a random session token for state-changing requests, and never connects to the production server. The isolated training server retains V1.0.54's `NODE_ENV=test`, `AI_TRAINING=1`, loopback, no upstream/auth bridge, and receipt checks. GPU datasets and model checkpoints remain on the local filesystem.

## Technical validation performed on V1.0.55

- 22 Node neural, model-commit, recovery, local-dashboard, and GPU-sample tests: passed.
- 2 PyTorch CPU-reference tests of the **same tensor math and JSON serialization**, including loss improvement and preserving `trainedGames`: passed. CPU-reference tests **do not count as a CUDA hardware test**.
- JS syntax checks and Discord Activity build/bundle verification: passed.
- Real CUDA training on the RTX 3090 Ti and end-to-end WebSocket self-play **could not be exercised in this environment**: the available PyTorch build is CPU-only, and npm dependencies could not be downloaded here. Run the desktop smoke test via `npm run train:neural:smoke` before a long job. For a CUDA trial, start a **small 20–50-game new run** in the dashboard and confirm `[cuda] batch ... weights updated` appears in logs and the model's `meta.lastCudaRefinement` field is set.

The new CUDA optimizer requires Python, PyTorch, and an NVIDIA GPU **only when CUDA mode is selected**. CPU mode, the shipped game, and existing tests remain independent of those Python dependencies.
